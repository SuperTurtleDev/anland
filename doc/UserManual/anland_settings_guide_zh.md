# Anland 设置使用说明

> [English](anland_settings_guide.md)

本文对应 Anland Android 应用中的“设置”页面。文中的“桌面”均指 Anland 正在显示的 Linux 桌面，不是 Android 主屏幕。

设置修改后会立即保存，不需要“保存”按钮；不过部分项目只能在建立桌面连接时读取。通常从设置返回 Anland 桌面时会重新连接并应用它们。

- 输入、扩展按键栏和显示布局类设置：返回桌面视图后生效。
- 连接、音频和输出分辨率：下次连接时生效；从设置返回桌面通常就会触发一次新连接。
- 屏幕方向：退出并重新打开 Anland 后生效。

<a id="keyboard"></a>
## 键盘与按键

<a id="soft-keyboard"></a>
### 软键盘切换键

<a id="bind-soft-keyboard"></a>
#### 绑定软键盘切换键

为 Android 的系统软键盘指定一个硬件按键。点击按钮后，Anland 会在 5 秒内记录下一次按键；倒计时结束前没有按键则清除绑定。

在 Anland 桌面有焦点时，按下这个键会显示或隐藏系统软键盘，该键不会再发送给 Linux 桌面。因此建议选一个平时不需要交给 Linux 的空闲按键。

<a id="raise-desktop"></a>
#### 软键盘弹出时抬起桌面

开启时，显示出来的软键盘和扩展按键栏会占用底部空间，Linux 桌面缩小到其上方，便于看到正在输入的位置。关闭时，显示出来的软键盘和按键栏浮在桌面画面上方，桌面保持原尺寸，但底部内容可能被遮住。

<a id="immersive"></a>
### 沉浸模式（实验性）

<a id="enable-immersive"></a>
#### 启用沉浸模式（实验性）

这是沉浸模式的总开关。开启它本身不会立即进入沉浸模式；还需要先绑定下方的切换按键，并在 Anland 桌面中按一次该键。

进入后，触摸屏、物理键盘、鼠标和触摸板等物理输入会直接交给 Linux 桌面，Android 的返回手势、状态栏和导航栏不会再抢走这些输入。它适合游戏、全屏应用或需要完整键鼠行为的场景。

此功能需要可用的 root 权限和至少一个可接管的输入设备。切换到其他应用、失去窗口焦点、锁屏或熄屏时，Anland 会自动退出沉浸模式并把输入还给 Android，以免无法操作系统界面。

原理上，Anland 的 root 辅助程序会临时独占这些输入设备，再将原始输入事件转发给 Linux 桌面；它不只是隐藏 Android 系统栏。

<a id="bind-immersive"></a>
#### 绑定沉浸模式按键

选择一个专门用于进入和退出沉浸模式的物理键。桌面中按一次进入，再按同一键退出。建议使用音量键或其他带扫描码的硬件键，并避免使用 Android 的屏幕导航手势。

如果绑定状态提示“该按键不上报扫描码”，该键不能用于沉浸模式；请重新绑定一个物理键。沉浸模式下 Android 已经收不到普通按键事件，因此退出键必须依靠这个原始扫描码由辅助程序识别。

<a id="accessibility"></a>
### 无障碍按键拦截

开启后，Anland 通过 Android 无障碍服务接收部分普通窗口难以收到的硬件键，例如 Fn 组合键和 F1–F12。它还会把部分平板键盘上报为“返回”或“浏览器后退”的 Esc 键转换为 Linux 的 Esc。

适用于外接键盘的功能键、Esc 或组合键没有正确传到 Linux 桌面时。首次使用需要在 Android 的“设置 → 无障碍”中允许 `Anland KeyInterceptor` 服务；若打开本开关后仍无效，请先完成该授权。

该服务只在 Anland 桌面窗口位于前台且有焦点时拦截按键，不会用来接管其他应用中的按键。

<a id="extra-keys"></a>
### 扩展按键栏

扩展按键栏是桌面底部的快捷键栏，默认包含 ESC、TAB、CTRL、ALT、方向键、HOME、END、PgUp、PgDn、软键盘按钮和设置按钮。它适合没有完整物理键盘时使用终端、编辑器或桌面快捷键。

默认布局中，CTRL、ALT 等修饰键轻点后只作用于下一次按键；长按可锁定，再次点击可解除。带重复属性的方向键、翻页键等可按住连续发送。向上划带有次级动作的按键可触发其弹出按键，例如默认的 `-` 可划出 `|`，`⌨` 可划出浮动虚拟键盘。

<a id="extra-keys-mode"></a>
#### 扩展按键栏模式

- 始终显示：进入桌面后一直显示按键栏。
- 不显示：默认隐藏按键栏。
- 随软键盘显示：只在 Android 系统软键盘显示时显示按键栏。

按键栏显示时会占用桌面底部空间；如果关闭了“软键盘弹出时抬起桌面”，它会改为叠加在桌面画面上。

<a id="back-extra-keys"></a>
#### 返回键快速切换扩展按键栏

开启后，在 Anland 桌面中按 Android 返回键可显示或隐藏按键栏。它是手动切换，因而即使选择了“不显示”也可临时叫出按键栏。

若同时开启“捕获外接指针”，第一次 Android 返回键会先释放鼠标/触摸板捕获；再按一次才会切换按键栏。

<a id="custom-extra-keys"></a>
### 自定义扩展按键布局

这里可直接编辑扩展按键栏的 JSON 布局。编辑器下方会显示“布局有效”或错误信息；无效或空的布局在返回桌面时会回退到内置默认布局。

<a id="load-default-layout"></a>
#### 加载默认模板

将编辑器替换为内置的两行默认布局。可在此基础上增删改按键。

<a id="load-layout-file"></a>
#### 从文件加载…

打开 Android 文件选择器，读取 JSON 或文本文件，并用其内容替换编辑器中的布局。文件内容会像手动编辑一样被校验和保存。

<a id="layout-format"></a>
#### 布局格式

最外层的 `rows` 是“行”的数组；每一行是“按键”的数组。一个最小示例如下：

```json
{
  "rows": [
    [
      {"label": "ESC", "type": "key", "code": 1},
      {"label": "CTRL", "type": "modifier", "code": 29},
      {"label": "⌨", "type": "keyboard", "popup": {"label": "VK", "type": "vkeyboard"}}
    ]
  ]
}
```

| `type` | 作用 | 常用字段 |
| --- | --- | --- |
| `key` | 向 Linux 发送一次按下和抬起 | `code` 为 Linux evdev 键码；可加 `"repeat": true` |
| `text` | 直接输入文本 | `text`；未填时默认使用 `label` |
| `modifier` | 切换 CTRL、ALT、SHIFT 等修饰状态 | `code` 为 Linux evdev 键码 |
| `keyboard` | 显示/隐藏 Android 系统软键盘 | 无 |
| `vkeyboard` | 显示/隐藏 Anland 的浮动虚拟键盘 | 无 |
| `settings` | 打开 Anland 设置页 | 无 |

任意按键都可加一个 `popup` 对象；从该按键向上划时执行 `popup` 的动作。`key` 和 `modifier` 的 `code` 是 Linux 的 evdev 键码，不是 Android 的 `KEYCODE`。绿色“布局有效”表示 JSON 结构可以加载；仍应确认键码本身是目标 Linux 系统支持的键码。

<a id="touchpad-mouse"></a>
## 触摸板与鼠标

<a id="touchpad-mode"></a>
### 触摸板模式（相对移动）

开启时，手指在屏幕上的滑动像笔记本触摸板一样移动鼠标光标，而不是直接点击屏幕对应位置。单指移动光标，轻点可左键点击，双指可滚动或轻点右键，长按后移动可拖拽。

关闭时，屏幕触摸会作为绝对位置的多点触摸直接发送给 Linux 桌面，适合触摸优化的应用、绘图或需要直接点按的位置。

<a id="pointer-capture"></a>
### 捕获外接指针

开启后，外接鼠标和物理触摸板使用相对移动并被锁定在 Anland 桌面内。鼠标移到屏幕边缘不会唤出 Android 状态栏或导航栏，适合桌面游戏和连续鼠标移动。

按 Android 返回键会临时释放捕获，方便操作 Android；随后点击 Anland 桌面画面即可重新捕获。屏幕触摸不受此设置影响。

即使此项关闭，Linux 应用在需要指针锁定时（常见于部分游戏）仍可能临时请求捕获；应用释放锁定后会自动恢复。

<a id="pointer-sensitivity"></a>
### 触摸板指针灵敏度（加速度,数字越高越灵敏）

调节相对移动的指针速度，范围为 0.5 到 10 倍。数值越高，快速滑动或移动鼠标时光标走得越远；较低值更利于精细定位。它主要影响屏上触摸板、被捕获的物理触摸板和相对模式的外接鼠标，不影响“直接映射到屏幕”的绝对触摸。

这里使用的是随移动速度变化的加速度，而非简单的固定倍数：慢速微调仍较稳定，快速移动会获得更明显的加速。

<a id="reverse-scroll"></a>
### 反向滚动

开启后使用“自然滚动”：手指向上推，内容随手指方向移动；关闭后使用传统滚轮方向。该设置同时影响屏上触摸板和被捕获的物理触摸板的双指滚动。

<a id="disable-multifinger"></a>
### 禁用双指开合与多指手势

开启后，双指捏合/张开以及三指或更多手指的手势会被忽略，不会传给 Linux 桌面。双指滚动和双指轻点右键仍可正常使用。

如果 Linux 桌面或应用会把多指输入误识别为缩放、切换手势，可开启此项。关闭时，这些不是滚动的多指手势会作为多点触摸转发给 Linux。

<a id="scroll-speed"></a>
### 双指滚动速度

调整双指移动转化为滚动量的速度。数值越高，同样距离的手指移动滚动越多；感觉滚动过快或过慢时再调整即可。

<a id="scroll-threshold"></a>
### 滚动判定阈值

决定双指移动多远后才被认定为“正在移动”。如果双指开合/捏合经常被错误识别为滚动，可降低这个值；若轻微抖动就开始滚动，可适当提高。

<a id="gesture-threshold"></a>
### 手势定性阈值

决定 Anland 何时把尚不明确的双指动作判定为滚动或其他手势。双指滚动开始得太迟、必须移动很远才有反应时，可降低此值；误判较多时可提高。

<a id="gesture-scale"></a>
### 手势幅度

当双指开合或三指以上动作没有被禁用时，Anland 会把它作为 Linux 多点触摸发送，并以当前鼠标光标为中心映射到一个正方形区域中。此项就是该区域的边长。

数值越大，同样的手指移动会在 Linux 中产生越大的触摸移动幅度。它只影响这些被转发的多指手势，不影响普通单指光标移动和双指滚动。

<a id="connection"></a>
## 连接

<a id="socket-path"></a>
### 守护进程套接字路径

这是 Anland Android 端连接显示守护进程的 Unix 域套接字路径，默认值为：

```text
/data/local/tmp/display_daemon.sock
```

通常不需要修改。只有桌面启动脚本把守护进程放在其他路径、或同时运行了多个独立守护进程时才需要填写。它是本机文件路径，不是 IP 地址或网络 URL。

路径错误、守护进程未启动，或目标不是 Unix 套接字时，Anland 无法打开桌面；首次启动时应用可能直接进入设置页，供你修正路径。

<a id="second-window"></a>
### 打开第二个窗口（独立守护进程与标题）

此区域可启动一个新的 Anland 窗口，适用于 Android 自由窗口、分屏或同时查看两个独立 Linux 桌面会话。

- 窗口名称：只用于该 Android 窗口在最近任务/自由窗口中的标题，例如 `work`；不会创建或重命名 Linux 守护进程。
- 套接字路径：新窗口要连接的守护进程。要获得真正独立的第二个桌面，应填写另一个正在运行的守护进程套接字。
- 打开第二个窗口：按当前填写内容启动。这里的名称和套接字只用于这次启动，不会替换主窗口保存的连接路径。

若第二个窗口指定的套接字已在某个 Anland 窗口中打开，应用会转到已有窗口，而不会重复连接同一个守护进程；若路径不存在，新窗口会提示失败并关闭。

<a id="root-connection"></a>
### 使用 root 连接（辅助程序）

开启后，Anland 通过 `su` 启动一个很小的 root 辅助程序，由它打开守护进程套接字，再把已建立的连接交回应用使用。

当套接字位于 Android 普通应用无权访问的位置时（例如某些 root 所有的目录），应开启此项并在 root 管理器中授权。关闭后，Anland 只能直接访问当前应用本身有权限读取和连接的套接字。

这不会改变 Linux 桌面本身的权限；root 只用于完成 Android 侧的受限连接。修改后在下次连接时生效。

<a id="foreground-scheduling"></a>
### 启用前台调度（root）

开启后，Anland 会把相关 Linux 桌面进程放入 Android 的前台调度组，提高它们获得 CPU 时间的优先级。桌面在系统繁忙时卡顿、当前应用响应慢时可尝试开启。

此功能需要可用的 `su`，并会增加耗电。它提升的是 CPU 调度优先级，不保证解决 GPU、网络或应用自身造成的所有卡顿；桌面本来流畅时建议保持关闭。连接结束时，Anland 会恢复原来的调度范围。

<a id="foreground-scope"></a>
#### 前台调度范围

- `1 - 当前焦点应用`：保持合成器和当前正在操作的 Linux 应用处于较高优先级；切换焦点时恢复前一个应用的普通优先级。适合日常桌面使用，影响范围较小。
- `2 - 整个桌面会话`：连接期间提升整个 Anland Linux 桌面进程树，包括后台应用和服务。性能优先，但功耗和对系统其他任务的影响更大。

<a id="scan-stop-processes"></a>
#### 扫描结束进程名（可选）

这是仅供非标准容器/会话结构使用的高级选项，不是“结束这些进程”。它告诉 root 辅助程序在向上查找 Linux 桌面会话的父进程时，遇到哪些进程名就停止，以便确定要提升的会话边界。

多个名称用英文冒号分隔，例如 `systemd:init`。留空会使用内置边界列表；填写内容会替换内置列表而不是追加。普通用户应留空，错误的列表可能导致提升范围过大、过小或无法生效。

<a id="microphone"></a>
### 将麦克风转发到桌面

开启后，Android 设备的麦克风会作为 Linux 桌面的录音输入，可用于会议、录音、语音聊天等。首次启用时需要允许 Android 的麦克风权限。

关闭此项不会影响 Linux 桌面的声音从手机/平板扬声器播放；它只关闭“手机麦克风 → Linux”的方向。为隐私和省电考虑，不使用录音时可保持关闭。

<a id="camera"></a>
### 将摄像头转发到桌面

开启后，Linux 桌面可把 Android 设备摄像头作为视频源使用。首次启用会请求 Android 相机权限；仅当 Linux 应用真正请求视频流时才会实际打开摄像头。

如果多个 Anland 窗口同时请求同一个摄像头，Android 只开启一条实际采集通路，并把同一画面提供给这些正在使用的窗口。

<a id="audio-keepalive"></a>
### 音频保活

开启后，Anland 保持手机端的音频输出通路活跃，使 Linux 桌面的短促声音，例如音量提示和按键音，能够更快地立即播放。

关闭时，桌面静默约 1.5 秒后音频通路会休眠以节省待机功耗；下一次有声音时会自动唤醒，短音可能更容易感觉到起音延迟。开启会略增待机功耗。

<a id="audio-latency"></a>
### 音频延迟

这两项分别调整音频通路的目标缓冲大小：

| 项目 | 音频方向 | 适用场景 |
| --- | --- | --- |

<a id="resolution"></a>
## 显示分辨率

<a id="resolution-values"></a>
### 预设、宽度和高度

此页设置的是 Linux 桌面渲染/输出的逻辑分辨率，不会改变 Android 设备面板的物理分辨率。较低分辨率通常能降低 Linux 桌面的渲染、显存和带宽压力；较高分辨率可带来更多桌面空间和更清晰的细节，但开销也更高。

预设包含：自动（`0×0`）、4K、2K、1080p、720p、480p，以及“屏幕 × 1.0 / 0.8 / 0.75 / 0.5 / 0.25”。选择普通预设会自动填入下方宽度和高度；“预设…”本身不改动当前数值。

“屏幕 ×”按当前 Android 面板的长边和短边（按横向计算）生成一组实际像素值，再写入宽度和高度。它不是持续跟随屏幕变化的倍率设置；选中时得到的是一组具体分辨率。

也可直接填写宽度和高度。使用自定义分辨率时，请填写两个正整数；选择 `0×0` 可回到自动使用 Anland 视图的原生尺寸。设置在下一次连接时发送给 Linux 桌面。

<a id="auto-stretch"></a>
### 自动拉伸显示

开启时，Linux 桌面画面会填满 Anland 窗口；若自定义分辨率与设备窗口宽高比不同，画面可能被拉伸。

关闭时，画面保持自定义分辨率的原始宽高比并居中显示，空出的区域为黑边（信箱模式）。Anland 会自动换算触摸和鼠标坐标，因此不需要因黑边手动调整输入位置。使用自动原生分辨率时通常不会出现黑边。

<a id="general"></a>
## 通用

<a id="orientation"></a>
### 屏幕方向

<a id="force-orientation"></a>
#### 强制屏幕方向

- 默认（跟随系统）：交给 Android 的自动旋转和系统设置决定。
- 强制横屏：Anland 只使用横屏方向；设备翻转时仍可在两个横屏方向之间旋转。
- 强制竖屏：Anland 只使用竖屏方向；设备翻转时仍可在两个竖屏方向之间旋转。

该设置控制的是 Anland Android 窗口的方向，不会改变 Linux 桌面内部的分辨率设置。修改后请退出并重新打开 Anland。

<a id="notification"></a>
### 设置通知

<a id="show-notification"></a>
#### 显示设置通知

开启后，Anland 桌面窗口在前台时会显示一条常驻的“Anland — 点击进入设置”通知，点击即可快速打开设置。关闭后不会显示这条通知。

在 Android 13 及更高版本，首次显示时还需要允许通知权限；系统通知渠道若被手动关闭，也不会显示。该通知只是设置入口，不用于保持守护进程或 Linux 桌面在后台运行；离开 Anland 时它会被移除。
